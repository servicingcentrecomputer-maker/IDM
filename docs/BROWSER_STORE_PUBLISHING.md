# Publishing the IDM browser extensions

Three store-ready archives are produced from this repository:

| Archive | Source | Target |
| --- | --- | --- |
| `IDM_Chrome_Extension.zip` | `extensions/chrome/` | Chrome Web Store |
| `IDM_Edge_Extension.zip` | `extensions/edge/` | Microsoft Edge Add-ons |
| `IDM_Firefox_Extension.zip` | `extensions/firefox/` | Mozilla Add-ons (AMO) |

Build them with:

```powershell
.\.venv\Scripts\python.exe scripts\package_extensions.py
```

The script validates required files, manifest version, browser constant,
permission minimality, the pinned Chrome/Edge key and the Firefox Gecko ID. It
writes the ZIPs to `dist-extensions\` with deterministic timestamps and prints
the SHA-256 of each archive. The ZIP root contains `manifest.json` directly,
which is what all three stores expect.

The same packages are generated by `build_windows.ps1` and shipped inside the
installer at `{app}\browser-extensions\`.

## Before submitting

1. Bump the version in `idm/version.py`, both version resources, the installer
   `MyAppVersion`, and all three `manifest.json` files. `build_windows.ps1`
   verifies consistency and stops on drift.
2. Run the full test suite.
3. Load each unpacked extension and complete the manual checklist in
   [BROWSER_INTEGRATION.md](BROWSER_INTEGRATION.md#verification), including the
   IDM-not-running fallback.
4. Prepare store listing assets: 128×128 icon (already in the package),
   screenshots of the popup and a transfer in progress, a short description, a
   long description, a support URL and a privacy-policy URL.
5. Confirm the native host is installed for the browser being tested and that
   **Test Connection** succeeds.

### Extension IDs and the allowlist

Chrome and Edge development builds embed a public key so the unpacked
extension keeps the ID `ljckgbgnolmopacdgmmgaijleadcmpgn`. The matching private
key was never kept; the key only pins an ID and does not sign packages.

Stores may assign a different ID (Chrome always derives it from the signing
key, Edge may do the same, and Firefox uses the Gecko ID declared in the
manifest). The desktop side must allowlist the **store** IDs before release:

- At runtime, the native host and desktop service read
  `IDM_CHROME_EXTENSION_ID`, `IDM_EDGE_EXTENSION_ID` and
  `IDM_FIREFOX_EXTENSION_ID` from the environment. If they are not set, the
  built-in development IDs are used.
- For a normal installation, update the constants in
  `integrations/browser_registry.py` and the `#define` values in
  `installer/IDM_Setup.iss`, then rebuild. The installer writes the manifests
  with the browser-specific `allowed_origins` / `allowed_extensions`.
- For manual registration, set the environment variables before running
  `scripts/register_native_host.py install`. The generated manifest uses the
  overridden ID.
- Firefox keeps `idm-browser-integration@idm.local` as its manifest ID. If AMO
  requires a different ID, change it in the Firefox manifest, the registry
  module and the installer define together.

Never ship a build that allowlists only the development ID when the store
version has a different one; the extension will connect but every request will
be rejected with `unauthorized_extension`.

## Chrome Web Store

1. Sign in to the [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole)
   with the publisher account and pay the one-time developer registration fee.
2. Select **New item** and upload `IDM_Chrome_Extension.zip`.
3. Fill in the store listing, category (Productivity), language, screenshots,
   support URL and privacy-policy URL.
4. Complete the privacy practices form. Declare:
   - **Downloads** — used to detect new browser downloads and cancel the
     browser copy after IDM accepts it.
   - **Native messaging** — used to talk to the locally installed IDM host.
   - **Storage** — stores the interception toggle and the last error.
   - No collection or sale of personal data, no remote code, no analytics.
5. Provide permission justifications for `downloads`, `nativeMessaging`,
   `contextMenus` and `storage`.
6. Submit for review. Store review can take days.
7. After approval, read the published extension ID from the dashboard. If it
   differs from the development ID, rebuild the IDM installer with the store ID
   (see above) and re-verify the popup connection.
8. Publish the IDM installer containing the updated allowlist before or together
   with the store listing. An extension released before the host accepts its ID
   cannot complete a download request.

Chrome Web Store policy requires a single purpose, minimal permissions and a
clear privacy disclosure. Do not add `tabs`, `webRequest`, content scripts or
host permissions for store convenience; they are not needed by this design.

## Microsoft Edge Add-ons

1. Create a Partner Center account and register as a Microsoft Edge program
   developer.
2. Create a new extension submission and upload
   `IDM_Edge_Extension.zip`.
3. Complete the listing: name, description, category, screenshots, privacy
   policy and support contact.
4. Declare the same permissions and data usage as for Chrome. Edge uses the
   same Chromium APIs and the same package layout.
5. Submit for certification.
6. Read the assigned extension ID after approval. Update the installer's Edge
   allowlist and `IDM_EDGE_EXTENSION_ID` if it differs from the development ID.
7. Install IDM from the updated installer and verify the popup and a real
   download.

The Edge package is independent of Chrome's; submit both if both stores should
list the extension.

## Mozilla Add-ons (AMO)

1. Sign in to [Mozilla Add-ons Developer Hub](https://addons.mozilla.org/developers/).
2. Submit `IDM_Firefox_Extension.zip` as a new add-on. The manifest already
   declares `browser_specific_settings.gecko.id` and
   `strict_min_version: 109.0`.
3. Fill in the listing and privacy policy. The extension uses
   `nativeMessaging`, `downloads`, `menus` and `storage`.
4. Choose **On this site** for unlisted/self-distribution or list it publicly;
   either way AMO signs the XPI required by release Firefox.
5. After signing, install the signed XPI and verify the native host connection.
   The host manifest's `allowed_extensions` must contain the same Gecko ID.
6. Note that the extension is Manifest V2 with a persistent background page.
   Firefox supports this at the time of writing; if AMO policy changes, migrate
   the background to a Firefox MV3 event page and retest the pause/resume logic.

AMO does not assign a different Gecko ID; the declared
`idm-browser-integration@idm.local` is used for signing and allowlisting.

## Installer and store coexistence

- The installer never downloads or silently installs a store extension. Users
  install the extension from the store themselves.
- The installer registers the native host only when the corresponding browser
  task is selected and the browser is detected.
- Updating IDM keeps the native messaging registration; the manifest path and
  host executable stay inside the installation directory.
- Uninstalling IDM removes only IDM's registry value and manifest. The store
  extension remains installed and reports that IDM is not available until the
  user removes it from the browser.

## Release checklist

- [ ] Version bumped in all manifests and application resources
- [ ] `pytest` green
- [ ] Manual interception and fallback tests passed on all three browsers
- [ ] Store IDs collected and allowlist updated
- [ ] Installer rebuilt with the store IDs and tested against the published
      extension
- [ ] ZIP SHA-256 values recorded with the release
- [ ] Privacy policy published and linked in all listings
- [ ] No development key, token or local path included in store packages
- [ ] Store listing states that IDM must be installed for functionality

## What is not automated

Store submission, review and listing are human processes. No credentials or
publisher tokens belong in this repository, and uploading packages is a
deliberate manual step. The repository has not submitted these packages to any
store; the instructions above describe the required process, not a completed
review.
